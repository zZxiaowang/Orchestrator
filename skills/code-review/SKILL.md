## 什么时候用

当这一步要**写或改代码**（新建模块、修 bug、重构函数）时，按下面清单过一遍再收尾。

## 自查清单

1. **边界**：空输入、超长输入、None / 缺字段、并发调用——函数在最坏输入下会怎样？
2. **错误处理**：失败要**可操作**（说清哪个字段 / 哪一步 + 怎么改），不要把底层异常直接抛给调用方。
3. **可测性**：新逻辑尽量是纯函数或可注入依赖；随机 / 时间 / 网络等外部因素要能被替换。
4. **命名与注释**：注释解释"为什么这样取舍"，而不是复述代码在做什么。
5. **改动面**：只碰这一步需要的文件；顺手改的东西单列出来说明。
6. **回归**：改完跑一次相关测试；没有测试就补一条最小的。

## 收尾时在 summary 里说明

- 改了哪些文件、为什么；
- 哪一条清单项有风险（没覆盖的边界要明确写出来）。
