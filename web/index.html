任务与验收

步骤越多纲领越细，但每一步都要单独过验收；建议 3–8 步。

验证命令

安全边界：不经过 shell（| & ; > % 等一律拒绝）、只在工作区内执行、 有超时与输出截断。危险命令不该进白名单。

普通对话：长上下文自动拆分（省 token）

普通对话默认把历史原样重发，聊得越久越贵。开启后按"滚动窗口 + 承接摘要"发送： 只带最近几轮原文，更早的压成一段摘要；摘要本身也撑不住时自动开新对话承接 （旧对话保留，可随时点回去）。项目里的运行不受影响——执行段的上下文始终是确定性裁剪。

每步上下文预算（省 token 的基本盘）

执行段每一步的新增上下文上限。超出后按"文件 → 工作区文件树"的顺序裁剪， 当前步骤与客观验收永不裁剪；预算不够时执行段会按需索取文件（need_files）。

MCP 工具调用

执行段可以在步骤里请求调用 MCP 工具（例如 filesystem / git / fetch）， 系统执行后把结果回灌给它继续做。工具本身仍要"已启用 + 已确认信任" （在「能力中心 → MCP」里操作），这里只是总开关与额度。

能力（skill / MCP）

安装与管理 skill、MCP 服务器都在能力中心：skill 是指令包（按需注入执行段）， MCP 是工具服务器（模型可请求调用）。会跑代码的能力默认关闭、需先确认信任。

插件（legacy）与 Git

Git 面板用于提交 / 推送 / 每日自动提交；插件市场安装声明式插件（不执行任意代码）。
