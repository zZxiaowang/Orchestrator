# 编排器 · 下一阶段架构契约（冻结版）

> 状态：**已冻结**（第 1 步产出）。后续实现步骤只能按本文件执行；
> 若确需变更决策，必须先改本文件并在第 7 节变更记录里写明理由。
>
> 适用范围：`app/`、`web/`、`scripts/`、`tests/`、`docs/`。
> **不适用** 于 `backend/`、`frontend/` —— 那是另一个产品的代码，禁止改动。

## 1. 目标与非目标

### 目标
在保持现有安全边界、轻量技术栈与向后兼容的前提下，为编排器补齐：
运行可观测性、故障降级、计划质量门、受控命令执行、大仓库检索、多轮续聊、并发队列、分发与常驻。

### 非目标（本阶段明确不做）
- 不引入数据库、消息队列、向量库、前端构建步骤或任何重型依赖。
- 不改动两段式（架构段 → 执行段）的基本分工，不放开“禁止模型自行压缩上下文”。
- 不做多用户、鉴权体系、云端同步。
- 不让执行段在缺少用户逐条确认的情况下执行任何命令。
- 不为统计看板引入外部监控依赖（Prometheus / OpenTelemetry 等一律不引）。

## 2. 优先级与退出条件

### P0 —— 可诊断性与成功率（步骤 2–6）
范围：2 指标数据契约、3 指标采集与统计接口、4 运行统计看板、5 主备配置自动降级、6 计划质量自检门。

退出条件（全部满足才算 P0 完成）：
1. 每步可读到 token 用量、耗时、上下文占用（字符数 + 估算 token）；**旧运行记录读入后这些字段有默认值、不报错**。
2. 统计接口可返回单次运行与全局汇总，数据只来自持久化文件，不依赖进程内状态。
3. 界面上有一块中文浅色统计区域展示上述指标；无数据时显示空态而不是报错。
4. 主配置在 502 / 429 / 超时 / 连接错误时可自动切到备用配置重试，且**同一逻辑步骤只提交一次**：重试发生在同一步骤内部，不产生新的步骤执行记录、不产生重复副作用。
5. 计划质量门能在纲领生成后判定粒度与可验收性，对“盘点现有代码”这类在工作区为空时不可执行的步骤给出明确拒绝或告警。
6. `python -m pytest -q` 全绿且用例数 ≥ 69；`node scripts/ui_check.mjs` 既有 25 项全绿。

### P1 —— 执行能力扩展（步骤 7–10）
范围：7 命令安全策略与生命周期、8 命令审批与输出回填、9 轻量工作区检索、10 既有运行多轮续聊。

退出条件：
1. 命令有显式生命周期状态，每一步可审计（状态定义见 `docs/state-and-event-contracts.md`）。
2. 命令默认不执行；只有同时满足「命中白名单」+「位于工作区边界内」+「用户针对本次命令的明确确认」三要素才可启动。
3. 命令输出以截断后文本回填到步骤记录，且受现有字符预算约束。
4. 检索能力在文件树之外提供关键词/索引式定位，结果同样受字符预算裁剪，路径越权防护复用现有实现。
5. 已完成的运行可继续对话；续聊产生的新步骤追加在原运行上，不破坏原有步骤记录与事件序号。

### P2 —— 部署与调度（步骤 11–13）
范围：11 持久化并发队列、12 可重复安装与启动入口、13 可选系统托盘常驻。

退出条件：
1. 队列状态持久化在单文件 JSON 中，进程重启后可恢复；并发上限可配置且有合理默认值。
2. 提供可重复执行的安装/启动入口（Windows 优先），停止/卸载可逆。
3. 托盘为**可选**能力：缺少依赖时程序仍能正常启动运行，不得成为硬依赖。

### 优先级理由
P0 的改动集中在“读”与“判断”上，风险最低却直接提升现有链路成功率；
P1 引入外部副作用（执行命令），必须先有 P0 的失败分类与可观测性做支撑；
P2 涉及资源调度与部署形态，在核心运行语义尚未稳定前引入会放大排障成本。

## 4. 兼容性规则（数据）

1. 单文件 JSON 存储不变，写入继续沿用现有原子化与并发保护策略。
2. 所有新增字段必须有默认值；`Run` / `RunStep` / `Settings` 的反序列化对旧数据必须成立；模型保持 `extra="ignore"`，未知字段不得导致读取失败。
3. 禁止复用已有字段的语义，只能新增字段或新增枚举成员。
4. 新增 `RunStatus` 成员（如 `queued`）只用于新流程，旧运行记录不会出现该值。
5. 「删除字段 / 改字段类型 / 改枚举值含义」均属破坏性变更，必须在本文件变更记录中登记并给出迁移方案。

## 5. 安全契约

- 命令执行三要素缺一不可：白名单命中、工作区边界内、用户对本次命令的明确确认。
- 三条既有规则全程不放松：路径越权防护、改动前备份、search/replace 全命中才写入。
- 自动重试不得产生重复副作用；重试只发生在同一步骤内部，并在步骤记录上留下最终错误信息。
- 敏感字段（API Key、Authorization 头、完整请求体）不得进入事件、日志、`run.json`、错误信封。

## 6. 交付门槛（Definition of Done）

任一实现步骤必须同时满足：
1. 有新增自动化测试覆盖新增分支（含旧数据兼容用例）。
2. `python -m pytest -q` 全绿，用例数不低于当步基线（基线见 `tests/baselines/README.md`）。
3. `node scripts/ui_check.mjs` 全绿（涉及界面的改动必须跑）。
4. 新增配置项写入 README，并给出默认值。
5. 不破坏既有 69 项后端测试与 25 项界面自检。
