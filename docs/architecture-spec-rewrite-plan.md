### 1.4 最重要的功能点（架构说明书必须优先讲清）

本项目的核心价值不是“有一个聊天界面”，而是把**想清楚、人工把关、逐步落地、可审计恢复**串成一条可靠链路。架构说明书应按以下优先级组织功能，不能把 Git、插件市场、外观和辅助工具放在核心编排能力之前。

#### F0：双模型分工与人工确认门——产品核心

- 架构段（GPT）：把自然语言需求转换成结构化、可验收的 `ArchitecturePlan`；
- 执行段（DeepSeek V4）：严格按 `RunStep` 一步一步修改工作区；
- 两段之间必须有 `awaiting_approval` 人工确认门；
- 用户可以反馈并重新生成纲领，确认后才允许执行。

**验收重点：** 规划和执行职责不混淆；未确认的纲领不得进入执行；每个步骤有目标、交付物和验收标准。

#### F1：安全的文件落地与变更审查——执行核心

- 工作区路径边界校验，禁止越权访问；
- 支持 create/update/delete 和 search/replace；
- 修改或删除前自动备份；
- 保存变更文件、diff、增删行数和错误信息；
- 前端展示变更审查，而不是只显示一句“完成”。

**验收重点：** 执行段只能改工作区内文件；失败不能静默覆盖原文件；每次改动可追踪、可复核、可恢复。

#### F2：上下文工程与按需取文件——成功率核心

- 将任务、前期简报、工作区树、当前步骤、已完成步骤交接信息分层组织；
- 使用字符预算裁剪上下文，避免长上下文无界增长；
- 执行段通过 `need_files` 按需索取文件，限制索取轮数和文件数量；
- 不允许模型自行压缩上下文，压缩策略由服务端控制。

**验收重点：** 空工作区时明确提示；模型不会因为上下文过长而失控；索取文件仍受路径边界和预算约束。

#### F3：运行状态、阻塞恢复与可审计事件——可靠性核心

- 运行状态：planning、awaiting_approval、executing、paused、blocked、done、failed、cancelled；
- 步骤状态：pending、running、done、failed、blocked、skipped；
- 支持取消、失败重试、blocked 后补充信息继续、进程重启后的恢复；
- EventBus/SSE 使用运行内单调 `seq`，支持增量订阅和断线续传；
- `run.json` 持久化完整状态，不能依赖进程内内存恢复。

**验收重点：** 已完成步骤不能因恢复而重复执行；blocked 只从阻塞步骤继续；事件顺序不依赖时间戳；每次状态变化可定位原因。

#### F4：模型路由、协议兼容与故障降级——可用性核心

- 架构段与执行段可以使用不同 Provider、Key、模型和协议；
- 支持 Chat Completions / Responses 等 OpenAI 兼容协议；
- 支持流式输出，并在必要时降级为非流式；
- 对超时、连接错误、502、429 等可重试故障进行分类；
- 主备配置自动切换必须发生在同一个逻辑调用/步骤内部，不得产生重复步骤记录或重复副作用。

**验收重点：** Key 不进入日志、事件、运行记录或错误文本；重试不会重复应用文件改动；路由信息只记录脱敏摘要。

#### F5：可观测性与计划质量门——当前最重要的 P0 补齐项

- 记录架构段和每个执行步骤的调用次数、重试、耗时、上下文字符数、token 用量及来源；
- 运行详情和全局统计都从持久化数据读取；
- 统计看板能区分真实 usage、估算 usage 和未知 usage；
- 纲领生成后检查步骤粒度、依赖关系、交付物和验收标准；
- 对空工作区下“盘点现有代码”等不可执行步骤给出拒绝或明确告警。

**当前状态：** 数据模型和部分测试已有，但指标采集主链路、统计 API、看板接线、计划质量门仍需在架构说明书中明确标为“部分实现/待开发”，不可写成已完成。

#### F6：后续扩展能力——重要但不应遮盖核心链路

按优先级进入演进章节，而不是放在核心架构之前：

1. **受控命令执行**：命令白名单、工作区边界、逐命令用户确认、输出截断回填和审计；
2. **大仓库检索**：关键词/索引定位，结果受预算控制；
3. **多轮续聊**：已完成运行继续追加步骤，不破坏旧步骤和事件序号；
4. **持久化并发队列**：重启可恢复，并发上限可配置；
5. **安装、常驻和可选托盘**：缺依赖不影响核心服务；
6. Git 面板、开机自动提交、插件市场和桌面体验优化。

这些能力都应建立在 F0～F5 的状态、审计、安全和可观测性之上。

### 1.5 功能优先级结论

后续开发和文档编排统一遵循：

```text
F0 双模型 + 人工确认
  → F1 文件安全落地
  → F2 上下文控制
  → F3 状态/恢复/事件
  → F4 路由/降级
  → F5 指标/质量门
  → F6 命令、检索、续聊、队列、部署与外围体验
```

如果某项功能不能回答“它如何提升规划正确性、执行安全性、恢复能力或可观测性”，则应归入外围能力，不得成为本轮架构说明书的主线。

## 2. 已确认的当前架构基线

### 2.1 产品与运行形态

- 产品：架构段（GPT）生成可验收纲领，人工确认后由执行段（DeepSeek V4）逐步落地文件改动；
- 形态：FastAPI 本地服务 + 原生 JavaScript/CSS 三栏工作台 + Windows WebView2 桌面客户端；
- 分发：PyInstaller 单文件或目录版；
- 数据：本地单机 JSON/Markdown 文件持久化，无数据库、消息队列、云同步和多用户隔离；
- 通信：REST 管理操作 + SSE 实时事件流；
- 模型接口：OpenAI 兼容的 Chat Completions / Responses 协议。

### 2.2 当前源码分层

| 层级 | 当前主要职责 | 主要源码落点 |
|---|---|---|

| 上下文层 | 分层上下文、字符预算、文件按需索取、交接摘要 | `app/services/context.py` |

### 2.3 核心运行链路

目标说明书必须准确覆盖以下真实链路：

1. 创建运行并确定目标工作区；
2. 架构段读取任务、简报、工作区树和补充说明；
3. 生成并解析 `ArchitecturePlan`；
4. 进入 `awaiting_approval` 人工确认门；
5. 执行段按 `RunStep` 顺序逐步调用模型；
6. 模型可通过 `need_files` 在有限轮次内索取文件；
7. `Workspace` 在边界内应用 create/update/delete，并在覆盖/删除前备份；
8. 步骤可进入 done/blocked/failed，运行可暂停、恢复、重试或取消；
9. `RunStore` 将 `run.json`、`plan.md`、`report.md` 持久化；
10. EventBus 通过带单调 `seq` 的 SSE 事件驱动界面刷新。

## 5. `docs/ARCHITECTURE.md` 目标目录

正式说明书按以下结构编写：

1. **文档目的、适用版本与状态图例**
2. **系统目标与非目标**
3. **系统上下文与信任边界**
   - 用户、本地客户端、本地 FastAPI、中转/直连模型端点、GitHub、插件目录源、文件系统；
   - 哪些调用离开本机，哪些数据只保存在本机。
4. **总体架构图**
   - UI/API/编排/模型接入/领域与持久化/外部集成六层图；
   - 桌面与浏览器两种启动形态共用同一后端的关系。
5. **核心领域模型**
   - `ArchitecturePlan`、`Run`、`RunStep`、`RunMessage`、`ChangedFile`、`PhaseMetrics`；
   - ID、状态、默认值、向后兼容和敏感字段约束。
6. **核心状态机**
   - 运行级状态；
   - 步骤级状态；
   - blocked/resume、failed/retry、paused/recover、cancel 的语义；
   - 未来续聊/queued 状态只放在“演进”小节。
7. **关键时序流程**
   - 创建运行与规划；
   - 人工确认与执行；
   - `need_files` 按需取文件；
   - 文件修改、备份和报告生成；
   - SSE 断线续传；
   - 进程中断后的恢复。
8. **模型接入与路由**
   - Provider、分段路由、协议、模型名；
   - `RelayClient` 的流式/非流式及参数兼容；
   - 备用路由模块的当前接线状态；
   - 不记录 Key 的规则。
9. **上下文工程**
   - 稳定背景、工作区树、当前步骤、历史交接、相关文件；
   - 字符预算和裁剪次序；
   - 为什么禁止模型自行压缩上下文。
10. **工作区与文件安全**
    - 路径解析、越界阻止、忽略目录、禁止路径；
    - create/update/delete、search/replace、备份、diff；
    - 空工作区与指定目标目录的不同语义。
11. **持久化与数据目录**
    - 源码版、打包版和 `ORCHESTRATOR_DATA_DIR`；
    - `run.json`、`plan.md`、`report.md`、workspace、backup、plugins、logs；
    - 原子写入和旧数据兼容。
12. **API 与事件接口**
    - 按运行、设置、Provider/路由、工作区、Git、市场/插件分组；
    - 统一写实际 `/api/v1` 前缀；
    - 事件信封、seq、history、heartbeat 和当前事件类型。
13. **前端架构**
    - 无构建步骤的原生 JS/CSS；
    - 三栏布局、弹层、命令面板、请求序号防竞态、错误上报；
    - 前端是后端状态的投影，不自行决定运行状态。
14. **Git 与自动提交集成**
    - 本地仓库范围、github.com 专用代理、Git 面板能力、开机自动提交边界。
15. **插件市场架构**
    - HTTPS 目录源、声明式清单、能力白名单、安装/启停/卸载；
    - 明确当前不是可执行任意代码的插件系统。
16. **安全模型**
    - 本地单用户假设；
    - Key 仅存 settings，禁止进入日志/事件/run.json；
    - 命令默认不执行；
    - 外部网络访问和插件源风险；
    - 当前没有多用户鉴权与命令沙箱。
17. **部署与打包**
    - 源码服务、演示实例、桌面客户端、PyInstaller 资源路径、数据目录回退；
