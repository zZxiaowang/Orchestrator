# 普通对话的长上下文管理：滚动窗口 + 承接摘要 + 自动开新对话

> 目的：普通对话聊得越久越贵（第 N 轮要把前 N-1 轮原样重发），需要一个既省 token
> 又不让用户"感觉上下文被吃掉"的机制。
> 实现：`app/services/chat_context.py`（装配）+ `Orchestrator._chat_reply` / `_start_followup_session`；
> 设置项在「设置 → 行为与上下文」；测试 `tests/test_chat_context.py`、`tests/test_chat_sessions.py`。

## 1. 核心判断

省 token 主要靠**窗口 + 摘要**，**开新对话**是摘要也撑不住时的重启阀，不是主要手段。

理由：用户心智里的"一段对话"是连续的。超阈值就悄悄换会话，下一句追问会撞上空线程——
省下的 token 换来的是"我的上下文被吃了"。所以新会话必须**可见、带承接链、旧会话留着**。

## 2. 三层结构（顺序固定）

```
system(稳定) → 承接摘要(滚动更新) → 最近 K 轮原文 → 当前提问
```

顺序固定是为了命中网关的**前缀缓存**：每轮变化的是尾部。若把 recent 放在摘要前面，
每次折叠都会让整段前缀缓存失效。

## 3. 折叠（会话内，无感）

| 规则 | 默认 | 说明 |
| --- | --- | --- |
| 保留原文窗口 | 最近 12 轮 / 6000 字符 | 双限，先到先算 |
| 折叠批量 | 每次 4 轮 | 不到一批就**先带着发**，不白丢上下文 |
| 摘要上限 | 300 字（提示词约束） | 只保留目标 / 已定结论 / 偏好约束 / 未决问题 / 关键事实 |
| 摘要合并 | 旧摘要 + 新溢出轮次 | 增量合并，不是每轮重算全量 |

摘要调用是**非流式**的（不能混进界面上"正在回答"的流），走同一个架构段端点、
**同样记账进指标**（折叠本身花了多少 token 看得见）。

## 4. 摘要失败怎么办

绝不阻断回答：捕获异常后退化为**确定性折叠**（各条取前 200 字拼成一行），
并在 `context_folded` 事件的 message 里写明"摘要模型不可用，用了原样折叠"。

## 5. 开新对话（可见、可回退）

触发：`承接摘要 > chat_summary_max_chars`（默认 2000 字，下限 200）且 `chat_auto_split` 开启。

行为：

1. 新建会话，`prev_session_id` 指向旧会话，`summary` / `folded_turns` 继承过去；
2. 本轮提问搬到新会话（旧会话不留半截问答）；
3. 旧会话追加一条 `phase="chat-split"` 的系统说明并记 `next_session_id`，**内容一字不删**；
4. 事件流推 `session_split`，界面自动切到新会话并提示；两段会话都能互相跳转；
5. `chat_auto_split=false` 时只折叠、不切换（保守模式）。

判定发生在 `send_chat_message`（发消息时），**不需要等模型**——摘要长度是已知的。

## 6. 与项目运行的关系（两套机制不要混）

* 执行段的每步上下文永远是**确定性裁剪**（预算 / 文件树 / 单文件 / 交接日志），
  可复现、可审计，不引入模型摘要；
* 运行内**不切换会话**：换会话等于换运行，会打断步骤、验收与 git 锚点的连续性。
  运行太长时的正解是开新一轮运行（带上一轮纲领摘要 + 已折叠的 done_log）；
* 因此「长上下文自动拆分」只作用于普通对话，关掉它不影响项目的任何行为。

## 7. 设置项（设置 → 行为与上下文）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `chat_context_enabled` | `true` | 总开关；关掉 = 全部历史原样发（旧行为，最贵） |
| `chat_window_turns` | `12` | 保留原文的最近轮数 |
| `chat_window_chars` | `6000` | 最近原文的字符上限 |
| `chat_fold_batch` | `4` | 每次折叠几轮 |
| `chat_summary_max_chars` | `2000` | 摘要超过该字数就开新对话（下限 200） |
| `chat_auto_split` | `true` | 关掉则只折叠并提示 |

界面上：总开关关掉时下面的可选项一起禁用，并在开关下方直接说明当前效果。

## 8. 可观测与验收

* 会话上记录 `folded_turns` / `summary` / `last_context_chars` / `prev_session_id` / `next_session_id`；
* 事件：`context_folded`（折叠了几轮、摘要多长、是否降级）、`session_split`（新会话 id 与标题）；
* 界面线程顶部显示「长上下文管理」卡片：已折叠 n 轮 · 摘要 n 字 · 上一轮发送 n 字符，
  并可展开看摘要、跳回上一段对话；
* 验收断言（`tests/test_chat_sessions.py`）：
  每轮发送的轮次被窗口限制住（不再线性增长）、摘要超限时自动开新会话且承接链双向可跳、
  关掉开关后行为与旧版完全一致（全量历史、零摘要调用）。
